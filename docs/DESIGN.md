# ARCANA FORGE 設計メモ

## 1. コンセプト

このゲームの目玉は**対戦以外の部分**、つまり「オリジナルカードの生成」。

- 原石を引くと**素質**がランダムに決まり、カードの**容量**（強さの上限）の倍率になる
- コストは自由に決められ、高いほど容量が大きい
- パワー・キーワード効果・テキスト効果が容量を使う。合計が容量に収まればカードの完成

対戦は、作ったカードを試す場であり、カードを作る動機になる場所。

## 2. 対戦のルール（企画書と、確認した細部）

| 項目 | 決めたこと |
|---|---|
| 勝ち方 | 相手の体力（5000）を0にする。山札0枚で引こうとしたら負け |
| ターンの流れ | ターン開始（自分のクリーチャーが全てアンタップ）→ 最大マナ+1・マナ全回復 → ドロー → メインステップ → アタックステップ → ターン終了 |
| マナ | 最大マナは0から始まり毎ターン+1、上限20（超高コストのカードを使いこなす戦い方のため） |
| 開始時 | 初期手札5枚。先攻の1ターン目はドローなし |
| 召喚酔い | 召喚したターンは攻撃できない（【速攻】は例外） |
| 攻撃 | 攻撃するとタップ。攻撃先は相手本体か、タップしている相手クリーチャー（【狙撃】はアンタップでも狙える） |
| バトル | パワーが大きい方が勝ち、負けた方は破壊。同じなら両方破壊 |
| 本体への攻撃 | パワーの分だけ体力が減る |
| 守護 | アンタップの守護が、攻撃を代わりに受ける（受けるとタップする）。ブロックという行動はない |
| 迎撃 | 〔迎撃〕の呪文は、相手のクリーチャーが攻撃した時に手札から唱えられる |
| デッキ | 40枚、同じカードは4枚まで。場は6体まで、手札は10枚まで |

### 先攻と後攻の差

CPU同士で測ると（各800戦）、補償なしでは先攻の勝率が約69%だった。後攻に次の補償を付けて約54%にした。

| 後攻の補償 | 先攻の勝率 |
|---|---|
| なし | 約69% |
| 初期手札+1枚 | 約66% |
| 初期手札+1枚、最初のターンだけマナ+1（採用） | 約54% |
| 初期手札+1枚、最初のターンだけマナ+2 | 約40%（後攻が強すぎる） |
| 初期手札+1枚、後攻の最大マナを1から始める | 約29%（後攻が強すぎる） |

マナ1の差がとても大きいゲームだと分かる。

## 3. カードを作る規則（`js/parts.js`）

### 容量

**容量 ＝（10 ＋ 10 × コスト）× 素質の倍率**（小数切り捨て）

| 素質 | 倍率 | 出やすさ |
|---|---|---|
| 鉄 | ×0.75 | 30% |
| 銅 | ×0.9 | 28% |
| 銀 | ×1.0 | 22% |
| 金 | ×1.15 | 12% |
| 白金 | ×1.3 | 6% |
| 星輝 | ×1.6 | 2% |

基本カードは全て「銀」で作っている。

### 容量の使い方

- **パワー**：パワー40ごとに1。5000を超える分は1.5倍（体力5000を一撃で削れる大型は割高に）
- **キーワード効果**：1つごとに決まった量（守護8、刺客14、速攻10、連撃16、貫通8、隠密10、不屈10、狙撃12、吸収8、加護8）。**デメリット**の【鈍重】（攻撃できない）は12、【自壊】（ターンの終わりに破壊）は18、容量が**戻ってくる**
- **テキスト効果**：効果の基本の量 ×「対象」の倍率 ×「発動の場面」の倍率 ×「条件」の倍率 ×「代償」の倍率

テキスト効果の部品：

| 部品 | 例 | 倍率の考え方 |
|---|---|---|
| 発動の場面 | 召喚した時(×1.0)、攻撃した時(×1.3)、自分のターンの始め(×1.6)、破壊された時(×0.8)、タップして発動(×1.2)… | 何度も起きる場面ほど高い |
| 条件 | 手札が1枚以下(×0.6)、自分の体力が2500以下(×0.75)… | 満たしにくいほど安い |
| 代償 | このクリーチャーをタップ(×0.7)、手札を1枚捨てる(×0.7)、体力を1000支払う(×0.65)… | 「〜してもよい。そうしたら」 |
| 効果 | カードを引く、破壊する、パワーを上げる/下げる、手札に戻す、相手にダメージ… | 効果ごとに基本の量 |
| 対象 | 1体を選ぶ(×1.0)、ランダムに1体(×0.75)、2体まで(×1.7)、全て(×2.5)… | 多いほど高い |

部品を選ぶと「召喚した時、手札が3枚以下なら、パワー2000以下の相手のクリーチャーを1体選び、破壊する。」のような文章が自動で組み上がる。

### 暴走を防ぐ決まり

- 「攻撃した時」「呪文を唱えた時」など何度も起きうる場面の効果は、**各ターン1回**まで
- 効果が効果を呼ぶ連鎖は12段まで
- 「このクリーチャーをアンタップする」は「攻撃した時」「バトルに勝った時」だけ
- 1枚に付けられるのは、キーワード効果3つ・テキスト効果2つまで
- カードコードを読み込む時も、同じ規則で容量を計算し直す（数値を書き換えた不正なカードは読み込めない）

## 4. 容量を「強さの物差し」として使う

容量はカードの強さの見積もりそのものなので、CPUもこれを使っている。

- 手札のどのカードを先に使うか：使った容量が大きいほど価値が高いとみなす
- 攻撃するかどうか：相手へのダメージ（パワー40につき1）と、タップして狙われる危険（クリーチャーの容量）を比べる
- CPUのカード作り：原石を引き、容量の5〜8割をパワーに使い、残りでキーワードと効果を試しに足し、最後に余りでパワーを上げる

## 5. 測定結果（CPU同士、`node tools/simulate.js`）

| 指標 | 値 |
|---|---|
| 1試合の長さ | 平均 約11ターン（1人あたり約5.7ターン）。ほぼ全て体力0で決着 |
| 決着時の最大マナ | 平均 約6 |
| 先攻の勝率 | 約54% |
| ランダム生成カード | 規則違反 0枚 |

## 6. 相談したいこと

**試合が短く、高コストのカードを使う前に決着がついてしまう**（決着時の最大マナは平均6）。最大マナ20まで伸ばして超高コストを使いこなす、という狙い（A2）と合っていない。

原因は、攻撃を防ぐ手段が【守護】しかなく、お互いに相手本体を殴り合う「速さ比べ」になりやすいこと。パワーの物差しを半分にしても1人約8ターンまでしか延びなかった。

考えられる対策：

1. **体力を増やす**（例：5000→10000）。いちばん単純
2. **防御の手段を増やす**：アンタップのクリーチャーなら誰でも攻撃を止められる「ブロック」を入れる、など
3. **マナの伸びを速くする**：最大マナ+2/ターン、マナを増やすカードを増やす、など
4. **このままにする**：短期決戦のゲームとし、20マナはマナを伸ばす戦略の到達点とする
